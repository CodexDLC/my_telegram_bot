# Руководство для разработчика

Этот гайд поможет вам настроить рабочее окружение, запустить бота для разработки и внести свои изменения в проект, следуя установленным стандартам.

## 1. Настройка окружения

### 1.1. Предварительные требования

- Python 3.12+
- Docker и Docker Compose (рекомендуется)
- Git

### 1.2. Установка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL репозитория>
    cd my_telegram_bot
    ```

2.  **Создайте файл конфигурации:**
    Скопируйте файл `.env.example` и переименуйте его в `.env`.
    ```bash
    cp .env.example .env
    ```
    Затем откройте `.env` и заполните его своими токенами:
    - `BOT_TOKEN`: Токен вашего Telegram-бота, полученный от @BotFather.
    - `OPENAI_TOKEN`: API-ключ от OpenAI.
    - `GEMINI_TOKEN`: API-ключ от Google AI Studio.
    - `DEFAULT_LLM`: Модель по умолчанию при старте (`openai` или `gemini`).

3.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python -m venv venv
    source venv/bin/activate  # Для Linux/macOS
    # venv\Scripts\activate    # Для Windows
    ```

4.  **Установите зависимости:**
    Все необходимые библиотеки перечислены в `requirements.txt`.
    ```bash
    pip install -r requirements.txt
    ```

## 2. Запуск бота для разработки

### Локальный запуск

Это самый удобный способ для написания кода и быстрой отладки.

```bash
python main.py
````

Бот запустится в режиме поллинга. Все изменения в коде потребуют перезапуска скрипта. Логи будут выводиться в консоль и в файл `logs/app.log`, как настроено в `app/core/log_setup.py`.

### Запуск через Docker

Этот способ имитирует production-окружение и полезен для проверки сборки и работы в изолированной среде.

Bash

```
docker-compose up --build
```

## 3. Стандарты кода и линтинг

Проект использует `Ruff` для форматирования и линтинга, а также `Mypy` для статической проверки типов. Конфигурации находятся в файле `pyproject.toml`.

- **Проверка всего проекта:**
    
    Bash
    
    ```
    # Линтинг и форматирование
    ruff check . --fix
    ruff format .
    
    # Проверка типов
    mypy .
    ```
    

Соблюдение этих стандартов обязательно перед созданием коммитов.

## 4. Как добавить новый режим работы

Следуйте этим шагам, чтобы добавить в бота новую функцию (например, "Генератор историй").

1. **Добавьте состояние (если нужно):** Если новый режим требует диалога, определите для него новое состояние в `app/resources/assets/states.py`.
    
2. **Определите пресеты:** В файле `app/resources/assets/dict_preset.py` добавьте новый `ChatMode` и пресет для него с системными инструкциями, температурой и т.д.
    
3. **Создайте "строители" промптов:**
    
    - В `app/services/gpt_service/chat_gpt_service_build.py` добавьте функцию-билдер для OpenAI.
        
    - В `app/services/gemini_service/gemini_service_build.py` добавьте функцию-билдер для Gemini.
        
    - Зарегистрируйте их в словарях `BUILDERS_GPT` и `BUILDERS_GEMENI`.
        
4. **Создайте кнопку в меню:** В `app/resources/keyboards/inline.py` добавьте инлайн-кнопку в `start_inline_kb()`, которая будет запускать новый режим.
    
5. **Напишите обработчик (Handler):**
    
    - Создайте новый файл в `app/handlers/callback/`, например, `story_generator.py`.
        
    - В нем создайте `Router` и напишите логику: обработку нажатия на кнопку, управление состоянием, вызов соответствующего сервиса из `llm_provider` и отправку ответа пользователю.
        
6. **Зарегистрируйте новый роутер:** Импортируйте и подключите ваш новый роутер в `app/handlers/__init__.py`, добавив его в `router.include_routers(...)`.
    

## 5. Отладка

- **Уровень логирования**: Для получения более детальной информации во время разработки вы можете изменить уровень логирования на `DEBUG` в `main.py`: `setup_logging(level="DEBUG")`.
    
- **Просмотр логов**: Логи выводятся в консоль, а также дублируются в файл `logs/app.log`. Это особенно полезно при запуске через Docker.
