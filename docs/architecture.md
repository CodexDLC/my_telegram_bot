
# Архитектура Telegram-бота "Мульти-Ассистент"

Этот документ описывает высокоуровневую архитектуру бота, его ключевые компоненты и логику взаимодействия между ними.

1. Общая схема

Проект построен на модульной архитектуре, где каждый компонент выполняет свою четко определенную роль. Это упрощает поддержку, тестирование и добавление нового функционала.

Основной поток данных выглядит следующим образом:

**Пользователь -> Telegram API -> Aiogram (Bot, Dispatcher) -> Router -> Handler -> Service -> LLM API (OpenAI/Gemini)**

```mermaid
graph TD
    A[Пользователь] --> B{Telegram API};
    B --> C[Bot/Dispatcher];
    C --> D{Главный Router};
    D --> E[Handlers];
    E --> F[Services];
    F --> G{LLM Provider};
    G --> H[OpenAI Service];
    G --> I[Gemini Service];
    H --> J[OpenAI API];
    I --> K[Gemini API];
````

## 2. Ключевые компоненты

### 2.1. Ядро (`app/core`)

- **`main.py`**: Точка входа в приложение. Отвечает за инициализацию логирования, создание объектов `Bot` и `Dispatcher` и запуск поллинга.
    
- **`config.py`**: Загружает конфигурационные данные (токены API) из переменных окружения (`.env` файла).
    
- **`bot_factory.py`**: Фабрика для создания и базовой настройки экземпляров `Bot` и `Dispatcher`.
    
- **`log_setup.py`**: Настраивает систему логирования с выводом в консоль и файлы, используя `colorlog` для удобства отладки.
    

### 2.2. Обработчики (`app/handlers`)

Модуль отвечает за обработку входящих обновлений от Telegram (сообщений, нажатий на кнопки).

- **`__init__.py`**: Собирает все роутеры из дочерних модулей в один главный `Router`, который затем подключается к `Dispatcher`.
    
- **`commands.py`**: Обработчики команд (`/start`).
    
- **`footer_menu.py`**: Обработчики для кнопок главного меню (`🏠 Меню`, `❓ Помощь`, `⚙️ Настройки`).
    
- **`/callback`**: Директория с обработчиками `CallbackQuery` (нажатий на инлайн-кнопки). Каждый файл отвечает за свой режим работы (квиз, чат, переводчик и т.д.), что делает логику изолированной.
    
- **`/setting_callback`**: Обработчики для меню настроек, например, для выбора LLM-модели.
    

### 2.3. Сервисы (`app/services`)

Сервисный слой инкапсулирует бизнес-логику и взаимодействие с внешними API.

- **`llm_provider.py`**: Абстрактный провайдер для работы с языковыми моделями. Это **ключевой компонент**, позволяющий динамически переключаться между `OpenAI` и `Gemini` для каждого пользователя или глобально. Он скрывает детали реализации конкретного сервиса от обработчиков.
    
- **`gpt_service/`** и **`gemini_service/`**: Пакеты, содержащие логику для взаимодействия с конкретными API. Включают в себя:
    
    - **`*_service.py`**: Клиент для отправки запросов к API.
        
    - **`*_service_build.py`**: "Строители" промптов. Они формируют полезную нагрузку для API в зависимости от выбранного режима (`chat`, `persona`, `quiz` и т.д.), добавляя системные инструкции и контекст.
        
- **`context_service.py`**: Сервис для управления историей диалогов. Хранит контекст беседы в памяти для каждого пользователя и режима.
    
- **`quiz_service.py`**, **`recommendation_service.py`**: Сервисы, отвечающие за парсинг и обработку JSON-ответов от LLM в соответствующих режимах.
    

### 2.4. Ресурсы (`app/resources`)

Содержит все статические данные, тексты, клавиатуры и ассеты.

- **`assets/`**: Словари с предустановленными данными: темы для квиза (`quiz_theme.py`), роли для режима "Личность" (`role_dict.py`), системные промпты (`dict_preset.py`) и состояния FSM (`states.py`).
    
- **`keyboards/`**: Модули для создания клавиатур (`inline.py` для инлайн-кнопок, `reply.py` для обычных).
    
- **`text/`**: Текстовые константы и шаблоны сообщений (`anonce.py`, `help.py`).
    

## 3. Управление состоянием (FSM)

Бот активно использует машину состояний (`FSM - Finite State Machine`) из `aiogram` для ведения диалогов, требующих контекста (например, в режимах чата, квиза, переводчика).

- Состояния определены в **`app/resources/assets/states.py`**.
    
- Обработчики используют `StateFilter` для срабатывания только в определенных состояниях.
    
- Контекст (`FSMContext`) используется для хранения временных данных пользователя в рамках одной сессии (например, выбранный язык для перевода или текущий счет в квизе).
